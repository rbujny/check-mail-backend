# API Gateway

Terraform provisions a Google Cloud API Gateway in front of the HTTP Cloud Functions.

## Public routes

The gateway uses the OpenAPI template in `infra/openapi/checkmail.yaml.tftpl`.

Current routes:

- `GET /health` routes to the `basic-http` function and requires a valid Checkmail JWT
- `POST /auth/token` routes to the `auth` function
- `GET /auth/jwks` exposes the public JWKS used by API Gateway to validate Checkmail JWTs
- `OPTIONS /health`, `OPTIONS /auth/token`, and `OPTIONS /auth/jwks` support CORS preflight requests

The OpenAPI document uses `x-google-backend` with `path_translation: CONSTANT_ADDRESS`, so public gateway paths are translated to the root path of each backend function.

## Client authentication

API Gateway validates JWTs before forwarding protected routes to backend functions. Protected routes require a bearer token in the `Authorization` header:

```sh
Authorization: Bearer <token>
```

Tokens are generated by `POST /auth/token`. That route and the JWKS route are intentionally public. Terraform also grants unauthenticated invoker access to the auth function so API Gateway can fetch the JWKS from the function URL.

The auth function signs tokens with `RS256`. Set `JWT_PRIVATE_KEY` through `function_env_overrides.auth` or another secret injection mechanism outside the repository. The corresponding public key is exported by the auth function at `/.well-known/jwks.json` and exposed through the gateway as `GET /auth/jwks`.

The issuer and audience expected by API Gateway are controlled by Terraform variables:

- `jwt_issuer`, default `checkmail-backend`
- `jwt_audience`, default `checkmail-clients`

## Backend authentication

Terraform creates a dedicated API Gateway service account and grants it `roles/cloudfunctions.invoker` on every discovered Cloud Function plus `roles/run.invoker` on the underlying Gen2 Cloud Run service.

The gateway sends an authenticated backend request using the function URL as the JWT audience. Do not grant public invoker access to functions unless direct access is required for a separate use case.

Terraform also enables the managed service created for the gateway API. This avoids a `PERMISSION_DENIED` response when clients call the deployed gateway hostname.

## Updating the OpenAPI config

API Gateway API configs are immutable. When the OpenAPI template changes, update `api_gateway_config_id` in Terraform variables, for example from `checkmail-api-config-v1` to `checkmail-api-config-v2`, before applying.

After `terraform apply`, use the `api_gateway_url` output as the public base URL.
